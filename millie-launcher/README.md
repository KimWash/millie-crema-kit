# millie-launcher — 밀리 래퍼

밀리의 서재를 여는 작은 앱입니다. 홈 화면의 **"밀리의 서재"** 아이콘이 이 앱이고, 원본 밀리 앱을 대신 띄워 줍니다. (패키지 `kr.co.millie.crema.launcher`)

## 문제 → 해결

| 문제 | 해결 |
|---|---|
| 밀리의 시작 화면(SplashActivity)이 4.2에서 멈춰 다음으로 안 넘어감 | 시작 화면을 건너뛰고 **로그인 화면(LoginActivity)을 바로** 엶. 저장된 로그인이 있으면 밀리가 알아서 내 서재로 넘어감. 시작 화면이 하던 초기화는 같은 앱의 `Splash` 서비스가 대신 띄움 |
| 기기가 잠에서 깨면 Wi-Fi가 "연결됨"으로 보이는데 실제 데이터는 안 흐를 때가 있음(특히 휴대폰 핫스팟). 밀리는 자동 로그인을 **한 번만** 시도하고 실패하면 로그인 화면에 멈춤 | Wi-Fi가 연결됐다고 할 때는 밀리 서버(`apis.millie.co.kr`)에 실제로 접속될 때까지 기다렸다가 엶. 30초가 넘으면 "다시 시도 / 그래도 열기" 화면 |
| Wi-Fi가 꺼져 있거나 10초 안에 연결되지 않으면 | 기다리지 않고 바로 오프라인으로 엶(밀리가 저장된 세션으로 로그인) |
| 밀리가 꺼진 뒤(직접 닫았거나 메모리 부족) 다시 열면, 안드로이드가 남겨 둔 화면 기록(로그인→책 보기)을 새 프로세스 위에 되살림. 이때 DRM 세션은 이미 없어서 **책 화면이 끝없이 로딩** | 밀리가 메모리에 없으면 남은 기록을 지우고(`FLAG_ACTIVITY_CLEAR_TASK`) 처음부터 시작. 밀리가 살아 있을 때는 보던 화면으로 돌아감 |

기다림 화면은 전자잉크에 맞춰 흰 바탕, 큰 글씨, 애니메이션 없음, 5초마다만 글자를 바꿉니다.

## 빌드

```
millie-launcher/build.sh                         # 로고 자리에 글자("밀리의 서재")
millie-launcher/build.sh --apk Millie-2.4.0.0.apk  # 원본 APK에서 로고·아이콘을 뽑아 씀
```
결과: `millie-launcher/out/millie-launcher.apk`. 밀리의 로고와 아이콘은 이 저장소에 넣지 않습니다.

서명 키(`local.keystore`)가 없으면 빌드할 때 새로 만듭니다. 이미 다른 키로 설치된 래퍼가 있으면 설치기가 지우고 다시 설치합니다.

## 설치

```
./install.sh --launcher [--apk Millie-2.4.0.0.apk]
```
`--webcompat`과 함께 설치하면 밀리가 첫 화면을 그렸을 때 래퍼에 신호를 주는 설정(`kr.co.millie.eink.shownsignal`)도 들어갑니다.

## 크레마 홈과의 관계

[`crema-home`](../crema-home/)은 밀리를 열 때 **항상 이 래퍼를 거칩니다**(홈, 앱 목록, 실행 중인 앱 화면 모두). 래퍼가 설치돼 있으면 원본 "밀리의서재 E ink" 항목은 앱 목록에서 숨깁니다. 원본을 직접 열면 멈추는 시작 화면으로 가기 때문입니다.
